# 독립 서버 간 작업 위임

공유 채널에 승인된 에이전트에게 메시지를 작업으로 맡길 수 있습니다. 실행은 해당 에이전트가 배치된 머신에서 진행됩니다. 작업을 요청한 서버에 성공 결과, 실패 상태 또는 확인된 취소 상태가 돌아옵니다.

## 사용 흐름

1. 관리자가 **서버 연결** 화면에서 상대 서버와 공유 채널을 연결하고, 참여자 공개와 채널 권한을 승인합니다. 설치·인증서 설정은 [두 서버 운영 가이드](runbook/federation-two-node.md)를 따릅니다.
2. 사이드바에서 공유 채널을 엽니다. 일반 참여자는 접근 가능한 공유 방에서 메시지를 보내고 작업을 요청할 수 있습니다.
3. 확정된 최상위 메시지의 **에이전트에게 맡기기**를 선택합니다. 이름, 설명, 서버와 준비 상태를 확인하고 대상을 선택합니다.
4. 같은 메시지의 작업 카드에서 진행 상태와 결과를 확인합니다. 중지 요청은 실제 정지가 확인된 후 취소 완료로 바뀝니다.
5. 전송 확인이 끝나지 않은 요청은 새로고침 후에도 남습니다. **전송 다시 시도**는 같은 요청을 확인하므로 새로운 실행을 만들지 않습니다.

결과가 불명확한 실행은 자동으로 다시 실행하지 않습니다. 권한 철회나 연결 단절 뒤에는 마지막으로 서버가 확인한 상태가 남을 수 있으며, 확인하지 못한 정지를 성공·취소 완료로 표시하지 않습니다.

## 실행 조건

- 서버, 머신과 에이전트를 호환되는 버전으로 함께 업데이트해야 합니다. 이 변경은 실행 중인 구버전 에이전트를 자동으로 재시작하지 않습니다.
- 대상 에이전트는 현재 머신에 배치되어 있고, 자신의 DM 제어 연결을 지원해야 합니다. 공유 채널의 활성 참여자이며 실행 가능한 역할과 현재 `task.execute` 권한이 필요합니다.
- 요청자에게는 현재 공유 권한과 `task.request` 권한이 필요합니다. 메시지 전송에는 `message.send`, 읽기·동기화에는 `channel.read`가 필요합니다. 권한 부여와 공개 동의는 별개입니다.
- 원격 실행은 POSIX의 Codex/Pi와 `restricted` 또는 `standard` 권한을 지원합니다. `trusted` 권한이나 구버전 클라이언트의 실행 경로를 임의로 대체하지 않습니다. Codex 기본 인증은 에이전트가 사용하는 로컬 `auth.json`이 필요하며, Direct 연결과 Pi 인증은 현재 에이전트 시작 설정에 등록된 자격증명을 사용합니다.
- 엔진·모델·공급자·자격증명·실제 작업 디렉터리는 대상 에이전트의 로컬 시작 설정을 사용합니다. 상대 서버가 파일 경로나 모델 키를 지정할 수 없습니다.
- 원격 실행에는 별도 런타임 홈을 사용하며 로컬 방의 MCP·Pi self-tools·서버 토큰을 전달하지 않습니다. Pi의 도구 제한을 운영체제 파일시스템 격리로 간주해서는 안 됩니다.

## 복구와 검증

앱 시작 시 공유 이벤트와 미확인 요청을 동기화하는 작업자, 실행 기록을 조정하는 작업자가 자동으로 시작됩니다. 느린 공유 동기화가 실행 권한 갱신을 막지 않도록 실행은 독립적으로 확인합니다. 실행 준비는 프로세스를 시작하지 않으며, 권한 확인과 수락 이후 영속 실행 의도를 기록한 뒤 시작합니다. 응답 유실 후에는 같은 실행 기록을 조회합니다. 준비 응답을 받기 전에 중지 요청이 들어와도 에이전트에 저장된 준비 정보를 확인해 정리하며, 이 조회는 실행을 시작하지 않습니다.

`packages/cluster/tests/test_federated_execution_flow.py`는 같은 테스트 호스트에서 별도 저장소의 제품 앱 두 개, 실제 mTLS, 실제 에이전트 WebSocket과 Codex 프로세스 어댑터를 사용합니다. 성공·엔진 실패·실행 전후 취소·준비 직후 취소·준비 ACK 및 시작 요청 유실 후 복구·결과 ACK 유실과 작업자 재시작·권한 철회 후 정지를 검증합니다. 모델 추론만 네트워크를 사용하지 않는 테스트 실행기로 대체하므로 실제 모델의 응답 품질이나 외부 공급자의 가용성을 검증한 결과는 아닙니다. 별도 외부 호스트에 배포하거나 공개 패키지를 배포한 검증도 포함하지 않습니다.
