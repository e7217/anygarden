# 멀티에이전트 플랫폼 목표와 완료 검증

사용자 목표: Supabase·Resend를 참고한 일관되고 깔끔한 UI/UX, Raft(구 slock.ai)를 참고한 멀티에이전트 작업 환경, 기존 기능 유지. 명시된 흐름은 에이전트 간 위임, 엔진별 생성 설정, 머신 간 위임, 에이전트 이름·역할·작업 공간·행동 이력이다.

이 목표는 #711 병합만으로 완료되지 않았다. 해당 PR은 공통 컨트롤과 생성·연결 실패 경로를 개선했다. 이번 문서는 기존 승인된 디자인의 기능 흐름을 끝까지 연결하기 위한 후속 설계와 완료 조건이다. 현재 구현을 목표 범위로 축소하지 않는다.

## 판단 기준과 접근

기존 승인된 라이트/다크·청록 강조·공통 크기·좌측 탐색/대화/맥락 패널을 유지한다. 새로운 화면을 별도로 늘리는 방식보다 현재 생성·설정·참여자·작업·활동 경로를 연결한다. 안내만 보강하면 실제 조회·저장·위임 누락이 남고, 전체 재작성은 기존 실시간/권한 기능을 불필요하게 흔들므로 기존 구조 안에서 실제 데이터 계약과 운영 동작을 완성한다.

## 이번 구현 단위의 조건표

| 화면·조건 | 표시·동작 |
| --- | --- |
| 방 참여자 최초 조회 | 에이전트 이름과 공개 역할 설명을 함께 전달. 사용자·게스트에는 에이전트 설명을 만들지 않음 |
| 역할 설명 변경/참여자 변경 | 기존 roster 갱신 이벤트로 현재 방 상태를 갱신. 이전 방의 지연 응답은 폐기 |
| 비관리자·게스트 | 접근 가능한 방의 참여자 공개 정보만 표시. 관리자 에이전트 API를 사용하지 않음 |
| 활동 첫 조회/에이전트 변경 | 로딩 표시, 이전 에이전트 이력 숨김 |
| 활동 조회 실패 | 실패와 재시도 표시. 빈 이력으로 오인하지 않게 함 |
| 활동 새로고침/이전 이력 | 현재 에이전트 범위의 안정된 시간·ID 순서로 조회. 중복·누락과 지연 응답 혼입 방지 |
| 설정의 작업/책임에서 방 이동 | 설정을 닫고 해당 방 대화로 이동. 기존 방 접근 권한 유지 |
| 소속 방 조회/추가/삭제 실패 | 상태·오류를 표시하고 실패를 성공 처리하지 않음. 저장된 소속 유지 |
| 방 전환 중 작업·목표의 지연 조회/변경 응답 | 현재 방과 요청 세대가 맞을 때만 반영. 전환 직후 이전 방 목록을 숨김 |
| `/delegate` 동시 요청 | 각 전달 요청에 고유 식별자를 붙이고 실행 결과가 같은 식별자를 반환할 때만 수집 |
| 위임 대상 방의 일반 메시지/다른 요청 결과 | 완료로 처리하지 않음. 대상 방의 에이전트 참여자와 요청 식별자 모두 확인 |
| 위임 실행 실패·시간 초과·전달 실패 | 성공 결과와 구분하여 원래 방/스레드에 보고. 콜백·타이머를 정리 |
| 작업 공간 | 실제 런타임이 보고한 위치·지원 범위를 근거로 설계. 엔진 이름이나 머신 ID에서 경로를 추측하지 않음 |

## 검증과 후속 단위

REST→참여자 UI·WS 갱신, 역할별 접근, 활동의 지연·실패·페이지 경계, 모달을 닫고 이동하는 실제 브라우저 흐름을 회귀 검증한다. 확인된 명시 요구를 완료하기 전에는 전체 목표를 완료로 표시하지 않는다.

별도 단위로 기본 작업 공간의 파일 확인 및 영속성, 머신/서버 경계를 넘는 위임의 실행·결과 회수, UI의 위임 상태 표시를 계속 구현·검증한다. 외부 폴더 root/audit 미지원(#491)을 안내로 숨겼다는 사실을 실행 기능의 완료 증거로 삼지 않는다.

독립 서버 위임은 필수 범위다. 요청 저장만으로 완료 처리하지 않으며, 제품 startup에 연결된 worker/runtime를 통해 상대 서버 실행, 원래 서버 결과·실패 상태 반영, 취소·중복 전달·재시작 복구와 권한 경계까지 검증한다. 외부 LLM의 과금 호출은 격리된 테스트 실행기로 대체할 수 있지만 실제 서버·전송·런타임 경로는 대체하지 않는다.

## 기존 책임 수정 조건

| 조건 | 표시·저장 계약 |
| --- | --- |
| 에이전트 설정에서 기존 책임 수정 | 현재 생성 폼의 제목·지침·일정·기록 정책·보고 방만 편집. 담당 에이전트와 소유자는 변경하지 않음 |
| 일정 종류 유지 | 서버에 저장된 trigger_config 추가 키를 보존하면서 해당 일정 입력만 갱신 |
| 일정 종류 변경 | 변경한 종류에 해당하는 설정을 저장 |
| 보고 방 입력 미변경 / 비우기 | 기존 값을 보존 / 명시적인 null PATCH로 해제. 서버의 방 참여 권한 검증 유지 |
| 저장 실패 / 에이전트 전환 중 저장 완료 | 입력과 오류를 유지해 재시도 / 새 에이전트 화면에는 이전 저장 결과·오류를 반영하지 않음 |

책임 수정은 변경된 필드만 PATCH한다. 제목·지침만 바꿀 때 일정 키를 보내지 않아 서버의 next_run_at가 불필요하게 재계산되지 않게 한다.
