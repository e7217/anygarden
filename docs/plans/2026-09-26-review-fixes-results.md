# UI·실행 흐름 리뷰 후속 수정 결과

2026-09-26. 승인된 14개 리뷰 항목을 반영했다. 기존 UI 개선은 보존했다. 아래는 구현 검증 시점의 결과이며, PR·병합은 #710에서 추적한다. 서비스 배포·머신 패키지 공개 배포는 별도 작업이다.

디자인 시스템을 구성했는데도 화면이 어수선했던 원인은 개별 컨트롤의 고정 크기, 공통 컴포넌트 적용 누락, 전역 CSS 우선순위 충돌이었다. 이를 수정하고, 생성·저장·선택 변경 시 실제 서버 상태와 화면이 달라지는 문제도 함께 해결했다.

## 리뷰 항목별 반영

| 번호 | 문제 | 반영 결과 |
| --- | --- | --- |
| 1 | 실행할 수 없는 외부 워크스페이스 선택지 | 서버가 머신·엔진·권한별 지원 여부와 이유를 반환한다. UI와 생성 API 모두 지원하지 않는 연결을 차단한다. 기본 데몬의 외부 폴더 실행 기능 자체를 구현한 것은 아니다. |
| 2 | 저장 후 실행 준비 실패에 따른 중복 생성 | 저장된 생성 결과와 실행 준비 실패를 분리했다. 사용자별 요청 키·설정 지문으로 재시도를 동일 생성으로 처리한다. |
| 3 | 대기 중 배치를 누락한 수용량 계산 | 대기·시작·실행·정지 중인 배치를 예약으로 집계하고 머신 잠금 안에서 검사·예약한다. 같은 에이전트의 재시작은 자신을 중복 집계하지 않는다. |
| 4 | 머신 전환 후 이전 상세 응답 반영 | `useMachineDetail`에서 선택 대상·요청 세대를 검사한다. 상세를 함께 갱신하고 실패·재시도를 제공하며, 조회 전에는 관련 운영 동작을 비활성화한다. |
| 5 | 연결 설정이 저장되지 않아 재실행 실패 | 기존 머신 ID와 토큰을 저장하는 `anygarden-machine connect`를 추가했다. 비공개 토큰 입력, 설정 충돌 방지, 원자적 파일 저장, 재실행 안내를 연결했다. |
| 6 | 내장 노드 워크스페이스 저장 경로 불일치 | 내장·원격 노드 안내를 구분하고 `--node-data-dir`로 실제 내장 노드 레지스트리를 지정한다. |
| 7 | 전역 관리자가 아닌 방 관리자의 승인 접근 불가 | 방 메뉴에 워크스페이스 관리 진입점을 추가했다. 방 관리자용 API를 사용하며 전역 승인과 방 승인을 구분한다. |
| 8 | 저장 성공 뒤 목록 조회 실패로 이전 권한 표시 | 저장 응답을 즉시 상태에 반영한다. 후속 조회는 저장 성공을 취소하지 않으며 이전 조회 결과가 저장 결과를 덮어쓰지 않는다. |
| 9 | 모델 변경 후 유효하지 않은 추론 값 저장 | 생성·수정 시 종속 값을 정규화하고 서버에서도 알려진 모델·엔진 조합을 검증한다. |
| 10 | 이전 연결 방식의 모델 조회 응답 혼입 | URL·인증·엔진·연결 방식 변경 및 컴포넌트 종료 후 오래된 조회 결과를 폐기한다. |
| 11 | 전역 테두리 규칙이 상태 스타일을 덮어씀 | 기본 테두리 규칙을 CSS base 계층으로 이동했다. 실제 브라우저에서 기본·포커스 테두리 계산값을 확인했다. |
| 12 | 모바일 패널의 포커스가 배경으로 이동 | 공통 드로어 훅으로 초기 포커스·Tab 제한·배경 비활성화·Escape·포커스 복귀를 처리한다. 중첩 대화상자도 확인했다. |
| 13 | 사이드바를 접어도 행 메뉴가 남음 | 접힘·숨김·기준 요소의 가시성 변경과 포털 메뉴 종료를 연결했다. |
| 14 | 개별 컨트롤 크기 불일치 | 언어·테마, 기간 선택, MCP 탭, 엔진 버튼, 북마크·답글, 오른쪽 작업·목표 컨트롤에 공통 크기를 적용했다. 모바일 주요 조작 영역은 44px 기준을 따른다. |

한영 전환은 계정 옆 개인 설정에, 접기·펼치기는 고정된 탐색 위치에 유지했다. 머신 페이지는 실행 환경 관리에 필요하므로 유지하고, 연결 상태와 배치된 에이전트를 상세 시스템 정보보다 먼저 배치했다. 연합 화면 제목 크기·안내 문구를 정리했고, 데스크톱에서 답글이 없는 메시지의 불필요한 빈 행을 줄였다.

## 검증

| 검증 | 결과 |
| --- | --- |
| 프론트 전체 Vitest | 81개 파일, 634개 테스트 통과 |
| 관련 백엔드·머신 CLI pytest | 262개 통과. 첫 통합 실행의 227개와 패키지의 비동기 설정으로 다시 실행한 35개를 합산했다. |
| Playwright | 26개 시나리오 통과. 최초 실행에서 실패한 테스트 선택자와 일시적 Chromium 요청 가로채기 오류는 수정·재실행으로 확인했다. REST 응답을 대체하는 UI 테스트다. |
| TypeScript·프로덕션 빌드 | `npm run build` 통과. 기존 대형 번들 경고는 남아 있다. |
| 실제 로컬 화면 | 9개 경로를 1440px 영어·라이트 / 375px 한국어·다크로 확인했다. 머신·채팅은 375·414·768·1024·1440·1920px에서 추가 확인했다. 검사한 컨트롤의 크기 미달·main/dialog 가로 넘침·페이지 JS 예외는 없었다. |
| 접근성 동작 | 양쪽 모바일 패널의 키보드 이동·Escape·포커스 복귀, 중첩 대화상자, 사이드바 접힘 시 메뉴 종료 확인 |
| DB 변경 | 추가형 마이그레이션 `077_agent_creation_requests` 검증. 기존 에이전트·DM·참여자·파일 및 제약 보존 회귀 테스트 통과. 로컬 개발 서버의 자동 마이그레이션 적용 상태도 확인했다. |
| 정적 검사 | `git diff --check` 통과. 전체 Ruff는 기존 진단 1,687건으로 미통과하며, 변경된 Python 파일의 HEAD 대비 진단 종류·메시지별 증가와 새 Python 파일 진단은 없었다. |

백엔드 검증은 생성 API·동시 배치·라이프사이클·마이그레이션·모델 연결·워크스페이스 지원과 승인, 머신 연결 설정·systemd·레지스트리·부트스트랩을 포함한다. 실제 사용자 머신·에이전트를 테스트용으로 생성·정지하거나 권한·접근 승인을 변경하지 않았다.

저장소 루트에서 pytest를 실행할 때에는 `-c packages/cluster/pyproject.toml` 등 패키지 설정을 지정해야 비동기 테스트의 `asyncio_mode = auto`가 적용된다.

## 남은 기능·배포 조건

- 기본 내장·원격 데몬은 외부 폴더 접근에 필요한 root/audit 기능을 제공하지 않는다. 쓰기 연결도 지원하지 않는다. 이번 변경은 실행 가능한 범위와 제한을 정확하게 표시하며, 별도 실행 어댑터·감사 기능 구현을 완료한 것은 아니다.
- 현재 로컬 머신이 오프라인이므로 실제 원격 엔진 실행과 외부 폴더 접근의 종단 검증은 수행하지 못했다.
- 웹의 새 연결 안내를 사용하려면 `connect` 명령이 포함된 머신 패키지와 프론트·API를 함께 배포해야 한다. 이전 공개 패키지에는 명령이 없을 수 있다. 설치·재실행 방법은 [머신 README](../../packages/machine/README.md)에 기록했다.
- 사용량 목록의 에이전트 UUID를 이름·상세 링크로 바꾸기, 연속 메시지 묶기, 대형 번들 분할은 이번 14개 수정 범위 이후의 개선 후보로 남아 있다.
