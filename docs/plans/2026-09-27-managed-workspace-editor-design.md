# 관리 작업 공간 웹 편집

## 목적과 경계

에이전트 설정의 **관리 작업 공간**에서 실제 실행 머신의 파일을 탐색하고, 폴더 생성·파일 업로드·UTF-8 텍스트 편집을 수행한다. 기존 `/agents/{id}/files`는 다음 실행 때 배포하는 manifest이며 실제 작업 파일과 분리한다. 외부 폴더 연결 및 다른 에이전트의 작업 공간은 편집 대상이 아니다.

현재 조회 API는 관리자 전용이며 배치 머신의 런타임 보고 경로를 사용한다. 같은 권한과 경로 경계를 편집에도 적용한다. 대안인 DB manifest 편집은 현재 디스크를 바꾸지 못하고, 클러스터 호스트에서 경로를 여는 방식은 원격 머신을 다룰 수 없다. 따라서 기존 인증 MachineBus 요청과 머신의 디스크 접근을 확장한다.

## 조건표

| 상태 | 표시와 동작 |
| --- | --- |
| 관리자·배치 머신 온라인·새 편집 capability·유효한 런타임 작업 공간 | 탐색, 새 폴더/텍스트 파일, 파일 업로드, 작은 UTF-8 파일 편집 |
| 관리자·기존 조회 전용 머신 | 기존 탐색 유지, 편집 도구 숨김·업데이트 안내 |
| 미배치·오프라인·런타임 경로 미보고·세대 변경 | 현재 상태와 재시도 안내, 편집 요청 불가/실패 |
| 일반 사용자·게스트 | 기존 관리자 API와 동일하게 접근 거부 |
| 숨김 인증 파일·외부 경로·링크·특수 파일·하드링크 | 조회 및 편집 모두 거부 |
| 기존 파일 업로드/새 파일 생성 이름 충돌 | 기존 파일 보존, 충돌 안내 |
| 화면에서 읽은 뒤 텍스트 파일 변경 | 저장 거부, 사용자의 입력은 화면에 유지 |
| 바이너리 또는 64 KiB 초과 파일 | 업로드 가능(최대 1 MiB), 텍스트 편집은 제공하지 않음 |

## 계약과 구현

- `GET .../workspace`/`GET .../workspace/file` 응답에 `can_edit`와 텍스트 파일의 SHA-256을 추가한다. 편집 기능을 광고하는 머신만 `managed_workspace_edit_v1`을 등록한다. 기존 조회 전용 버전은 그대로 탐색된다.
- `POST .../workspace/folder`는 상대 `path`를 받는다. `POST .../workspace/upload`는 상대 `path`와 최대 1 MiB의 base64 본문을 받아 **새 파일만** 만든다. `PUT .../workspace/file`은 상대 `path`, 최대 64 KiB UTF-8 텍스트, 읽을 때 받은 해시 또는 `absent`를 받는다. `absent`는 새 파일 생성 전용이다.
- 서버는 관리자·현재 배치/세대·머신 capability를 검증하고, 상대 경로와 본문 크기를 제한한 뒤 MachineBus로 요청한다. 응답 직전에 배치/세대를 다시 확인한다. 파일 본문은 DB·로그에 기록하지 않는다.
- 머신은 실제 런타임이 보고한 관리 root를 재확인한다. POSIX 디렉터리 descriptor와 `O_NOFOLLOW`로 부모를 순회하고, 최종 항목의 종류와 하드링크를 검사한다. 동일 디렉터리에 임시 파일을 만든 뒤 동기화하고 교체한다. 새 파일과 폴더는 기존 항목을 덮어쓰지 않는다. 숨김 파일/비밀 이름 차단, 세대·실행 프로세스 확인 및 Windows 미지원은 기존 조회 경계를 따른다.
- UI는 파일을 읽은 후에만 편집기를 연다. 저장 결과가 실패/충돌이면 입력을 유지한다. 선택한 에이전트·폴더·파일이 바뀐 뒤 도착한 응답은 화면에 반영하지 않는다. 모바일에서도 도구가 줄바꿈되고 조작 크기를 유지한다.

에이전트 실행 중 같은 파일을 에이전트가 직접 바꾸는 경합은 저장 직전 해시 검사로 감지한다. 에이전트 프로세스는 웹 편집 잠금을 사용하지 않으므로, 외부 도구와의 완전한 원자적 편집 직렬화까지 보장하는 계약은 아니다. 운영 반영 시 서버와 머신 패키지를 함께 업데이트해야 한다.
