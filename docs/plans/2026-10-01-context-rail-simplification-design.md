# 채팅 컨텍스트 패널 단순화

사용자 승인 방향: 2026-10-01, 오른쪽 패널부터 요약 → 상세 구조를 구현한다.

## 선택한 접근

기존 섹션을 재사용해 조치할 질문·승인 → 현재 실행·작업 → 최근 결과·이력 → 책임·파일 순으로 정리한다. 전체 기능을 탭으로 이동하면 조치가 숨겨지고, 패널 전체를 새 데이터 모델로 다시 만들면 실시간 상태·권한 회귀 범위가 커진다. 기존 섹션의 정보량과 상태 분류를 먼저 개선한다.

## 표시 조건

| 데이터 상태 | 기본 표시 | 상세·행동 |
|---|---|---|
| 현재 대기 질문 | 제목·대기 상태 | 펼치면 질문 원문과 답변, can_answer 유지 |
| 현재 대기 승인 | 작업·대상·승인 대기 | 펼치면 파일·대상·영향과 결정, can_decide 유지 |
| 현재 실행 | 목표 최대 2줄·상태·입력 버전 | 상세에서 사용량·원 요청·이력·입력 변경·취소 |
| 현재 작업 | 제목·담당·대표 상태 | 처리 이력과 결과는 펼쳐서 확인 |
| 취소 완료·이전 입력 작업 | 진행 목록에서 제외 | 이력에서 원래 상태·결과·취소 설명 확인 |
| 취소/중지 확인 대기 | 확인 대기 상태 | 취소 완료로 표시하지 않음 |
| 완료 작업 | 최근 3건 | 나머지는 전체 이력에서 확인 |
| 책임·공유 파일 | 접힌 관리 영역 | 기존 생성·수정·업로드 경로 유지 |

작업의 상태와 실행 disposition을 구분한다. 완료 결과는 보존하고, 취소·이전 입력을 현재 진행으로 표현하지 않는다. deadline/limit 종료는 일반 취소와 다른 문구를 사용한다. 백엔드 계약과 저장 값은 변경하지 않는다. 받은편지함은 이번 구현 범위 밖이며 공용 카드의 기본 동작을 유지한다.

## 검증

상태 분류 단위 테스트, 관련 컴포넌트 테스트 및 패널 브라우저 테스트. 실제 서비스에서 모바일·태블릿·데스크톱 및 한영·라이트다크를 한 차례 묶어서 점검한다. 펼친 승인에서 대상과 영향이 결정 버튼보다 먼저 표시되는지 확인한다.

## 구현과 검증 결과

- 질문·승인은 접힌 요약에서 원문·결정 내용을 열고, 기존 권한 검사와 입력 초안을 유지한다. 받은편지함의 공용 카드 기본값은 기존 펼침 동작을 유지한다.
- 실행은 목표 2줄·상태 중심으로 요약하고 사용량·관리·이력을 상세로 이동한다.
- 작업은 현재 상태·취소·이전 입력을 구분한다. 상태별 첫 5건, 최근 완료 3건을 표시하고 모든 나머지 기록에 펼침 경로를 제공한다.
- 단위·컴포넌트 테스트 24개, 기존 Playwright 패널 테스트 10개 통과. 프론트엔드 빌드 통과.
- 실제 서비스 375/768/1024/1440px × 한국어/영어 × 라이트/다크 16개 조합 점검. 펼침 아이콘을 한 차례 수정 후 모바일·데스크톱의 라이트·다크 4개 조합 재확인. 가로 넘침·JavaScript 오류 없이 질문 초안 유지 확인.
