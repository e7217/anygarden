# Anygarden 제품 UI/UX 개편 설계

> 2026-09-26 사용자 승인: 전체 제품 경험, 라이트 기본 + 다크 모드, 한국어·영어 전환, 청록색 강조.

## 목표와 확인한 문제

기존 React 19, Tailwind v4, Radix/shadcn 방식 컴포넌트와 서버 계약을 유지하면서 로그인부터 채팅, 관리자 및 게스트 화면까지 일관된 작업 경험을 제공한다. 데스크톱 채팅의 좌측 탐색–대화–선택형 우측 맥락 구조는 유용하다. 모바일과 태블릿에서는 이 구조를 화면 폭에 맞춰 다시 배치해야 한다.

실제 브라우저에서 다음을 확인했다.

- 375px 채팅방 헤더에서 참여자 버튼이 메뉴 버튼의 포인터 이벤트를 가로채 메뉴를 열 수 없다. `RoomHeader.tsx`의 오른쪽 고정 컨트롤과 제목 영역이 충돌한다.
- 375px과 768px의 머신 화면에서 고정 256px 머신 목록 옆 상세 열이 지나치게 좁아진다. 375px에서 상세 정보가 한 글자씩 줄바꿈된다.
- 375px의 스킬 화면에서 `Register skill` 버튼이 화면 밖에 완전히 놓인다.
- 사용량 화면은 모바일에서도 3열 지표를 유지하고, 보조 설명이 읽기 어렵게 줄바꿈된다.
- 첫 방문 빈 채팅 화면에는 프로젝트·방 생성 실행 버튼이 없다. 조작 영역과 옅은 보조 글자도 다수 있다.
- 정적 UI 문구가 한국어와 영어로 섞여 있고, 현재 색상 토큰은 라이트 모드만 정의한다.

## 선택한 접근

세 접근을 비교했다. 색·타이포만 바꾸는 방법은 빠르지만 작동 장애를 해결하지 못한다. 정보 구조와 프론트엔드를 전면 재작성하는 방법은 변경 자유도가 높지만 실시간 채팅·권한·설정 흐름의 회귀 부담이 크다. **기존 구조를 기반으로 디자인 시스템과 주요 흐름을 단계적으로 개편**한다.

[Supabase 문서](https://supabase.com/docs/guides/database/overview)의 명확한 탐색 그룹, 본문 중심 레이아웃과 모바일의 보조 레일 축소, [Resend 공개 대시보드 샘플](https://resend.com/static/product-pages/screenshot-metrics.png)의 절제된 경계와 정보 위계를 참고한다. Resend의 실제 로그인 후 대시보드는 확인하지 못했으므로 공개 샘플의 시각적 특성만 참고한다. 브랜드 자산과 화면을 복제하지 않는다.

## 시각 체계

- 밝은 중립 배경, 흰 작업 면, 진한 중립 글자, 단일 청록색 상호작용 강조를 사용한다. 상태 색은 성공·주의·오류의 의미로만 쓴다.
- 라이트와 다크는 의미 토큰(`background`, `surface`, `foreground`, `muted`, `border`, `brand`, 상태색)을 공유한다. 토큰은 CSS 변수를 원천으로 하고 Tailwind 유틸리티 및 shadcn 컴포넌트가 이를 소비한다.
- 제목·섹션·본문·보조 글자·배지의 위계를 통일한다. 일반 본문은 16px, 주요 보조 글자는 최소 14px을 목표로 한다. 작은 상태 배지는 정보 보조에 한정한다.
- 본문 대비 WCAG AA 4.5:1, 상태·포커스·선택 상태는 색 이외의 텍스트·아이콘도 사용한다. 터치 조작 영역은 최소 44×44px을 목표로 한다.
- 라이트 모드를 기본으로 하며, 사용자는 로그인 전후에 테마를 바꿀 수 있다. 선택은 브라우저에 저장하고 첫 페인트 전에 적용해 화면 번쩍임을 피한다.

## 레이아웃과 흐름

### 공통 프레임

데스크톱에는 기능별로 묶은 탐색과 현재 위치를 표시한다. 채팅은 좌측 프로젝트·방 탐색, 중앙 대화, 사용자가 여는 우측 작업·목표·파일 맥락을 유지한다. 1024px 이하에서는 여유 폭에 따라 레일을 축소하고, 모바일은 한 번에 하나의 주 작업 면을 보여준다. 탐색은 드로어, 맥락은 별도 패널로 연다. 모든 페이지 헤더는 제목, 설명, 주 액션, 보조 액션의 순서를 따른다.

### 로그인·첫 사용

로그인과 회원가입에 언어·테마 전환을 제공한다. 성공·실패·진행 중 상태를 같은 패턴으로 보여준다. 프로젝트가 없으면 프로젝트 생성, 프로젝트는 있으나 방이 없으면 방 생성, 접근 가능한 방이 있으면 방 선택으로 이어지는 직접 실행 버튼을 빈 화면에 제공한다.

### 방·채팅

모바일 헤더에서 메뉴, 방 제목, 상태, 추가 액션이 겹치지 않게 두 줄 또는 축약 메뉴로 재구성한다. 대표 에이전트·참여자·검색 등은 공간에 따라 노출하되 기능에 도달할 경로를 유지한다. 대화와 입력기는 충분한 읽기 폭을 갖고, 첨부·전송·오류 상태를 일관되게 표현한다. 저장된 방·에이전트 설정과 기존 사용자 경로는 유지한다.

### 관리자·게스트

머신은 넓은 화면에서 목록–상세 2열, 좁은 화면에서 목록→상세의 한 열 흐름으로 전환한다. 스킬·MCP·사용량·시스템·연합·토폴로지 페이지는 동일한 헤더, 빈 상태, 필터, 액션, 상태 표시 패턴을 사용한다. 다이얼로그는 모바일 가장자리 여백과 최대 높이, 내부 스크롤, 도달 가능한 하단 액션을 갖는다. 삭제·복구 불가·토큰 변경 등은 일관된 확인 다이얼로그로, 비동기 결과는 일관된 피드백으로 표시한다. 게스트에게는 관리자 조작을 노출하지 않는다.

설정 선택지는 화면을 수정하기 전에 역할(관리자·방 소유자/관리자·일반 참여자·게스트), 상태(온라인/오프라인, 생성/수정, DM/일반 방), 선택값별로 **적용 가능한 조합·기본값·표시 입력 항목**을 표로 검증한다. 기존 값과 API의 읽기·수정 경로가 없는 숨은 설정을 만들지 않는다.

### 책임 생성 입력 조건

| 맥락·선택 | 기본값 | 표시 입력 | 추가 조건 |
| --- | --- | --- | --- |
| 방 맥락, 참여 에이전트 1명 | 해당 에이전트 | 제목·지시문·반복 방법·담당 에이전트 | 담당 에이전트는 표시하되 변경 불가 |
| 방 맥락, 참여 에이전트 2명 이상 | 첫 에이전트 | 위 항목 | 담당 에이전트 선택 가능 |
| 에이전트 설정에서 생성 | 현재 에이전트 | 위 항목 | 방 보고 대상은 기본 비움 |
| 일정 `cron` | `0 9 * * *` | cron 표현식 | 간격 초 입력 숨김 |
| 간격 `interval` | 600초 | 간격 초 | cron 입력 숨김 |
| 수동 `manual` | — | 반복 입력 없음 | 실행은 생성 후 사용자가 시작 |
| 고급 설정 닫힘 | 관심 결과만 기록, 방 맥락이면 현재 방에 보고 | 일반 입력만 | 기록 정책과 보고 방 ID는 고급 설정에 보관 |
| 고급 설정 열림 | 저장된/기본값 유지 | 기록 정책·보고 방 ID | 방 ID를 비우면 조용히 실행 |

이 구성은 기존 API 필드와 저장 값을 그대로 사용한다. 생성 화면에서만 기본 경로의 입력 밀도를 줄인다.

## 한국어·영어 전환

고정 UI 문구, 접근성 레이블, 빈 상태, 알려진 오류 메시지를 번역 카탈로그에서 가져온다. 프로젝트 이름, 사용자 메시지, 에이전트 출력, 서버에서 온 임의의 기술 상세는 번역하지 않는다. 브라우저 언어가 한국어면 한국어, 그 외에는 영어로 시작하고 사용자의 명시적 선택을 우선해 브라우저에 저장한다. 언어 변경은 새로고침 없이 적용한다. 날짜·시간·숫자도 선택 언어에 맞춰 표시한다.

## 구현 단위와 검증

1. 의미 토큰, 라이트·다크, 공통 폼·버튼·다이얼로그·상태·피드백, 번역 기반을 만든다.
2. 로그인, 첫 사용, 탐색, 채팅 헤더·입력기·맥락 패널을 개선하고 확인된 클릭 장애를 수정한다.
3. 머신·스킬·MCP·사용량·시스템 관리자 화면을 모바일 우선 구조로 정리한다.
4. 연합·토폴로지·게스트 경로를 같은 체계로 맞추고 남은 고정 문구를 번역한다.
5. `DESIGN.md`를 실제 토큰·레이아웃·언어 정책에 맞춰 갱신한다.

각 단위는 기능 회귀 테스트와 375/768/1024/1440px 실브라우저 점검을 거친다. 핵심 기준은 모든 주 액션에 도달 가능할 것, 가로 화면 밖으로 조작이 사라지지 않을 것, 채팅·설정의 기존 서버 계약과 저장된 값이 유지될 것, 라이트·다크 및 한·영에서 읽기와 조작이 가능할 것이다.
