# UI 일관성 및 실행환경 온보딩 개선

2026-09-26 사용자의 전반 개선 구현 요청에 따라 기존 제품 개편 설계를 보완한다.

## 확인한 문제와 방향

- `cn()`의 tailwind-merge 설정에 사용자 정의 글자 크기가 등록되지 않아 `text-lead`·`text-heading` 등이 색상 클래스로 오인되어 제거된다. 이름만 토큰화한 상태와 실제 적용이 달랐다.
- 색상 토큰이 있어도 컨트롤의 높이·패딩·타이포 규칙은 화면마다 다르다. `min-height`와 기존 패딩, 직접 구현한 44px 버튼이 섞여 데스크톱 밀도가 깨진다.
- 사이드바는 모든 행을 44px로 늘리고 언어·테마 줄을 추가한 반면 보조 아이콘은 24px여서 위계가 어긋난다.
- 머신 등록은 토큰 표시에서 끝나 설치·접속 주소·실행·연결 확인을 사용자가 추측해야 한다.
- 에이전트 생성에 기존 API의 설명·룸 연결이 누락되고, 선택 머신과 실제 자동 배치가 일치하지 않는다.

색만 재조정하는 방법은 기능 누락을 해결하지 못하며 전면 재작성은 실시간 기능 회귀 부담이 크다. 기존 구조·테마·API를 유지하면서 공통 컨트롤 크기와 실제 사용자 경로를 정리한다.

## UI 계약

데스크톱 기본 입력/버튼 36px, 작은 버튼/아이콘 32px, 모바일과 coarse pointer 44px. 실제 높이로 구현하여 padding 합산으로 커지지 않게 한다. 페이지 제목 24px, 다이얼로그/카드 제목 20px, 본문/레이블 14px, 보조 메타데이터 12px. 각 컴포넌트의 기존 예외적 레이아웃은 유지한다.

언어·테마는 로그인 후 계정의 개인 설정에 모은다. 로그인 전 전환 위치는 유지한다. 데스크톱 왼쪽 탐색은 접어도 56px 레일을 남겨 토글이 같은 좌표에 있고 본문과 겹치지 않게 한다. 오른쪽 맥락 토글은 채팅 헤더 끝에 유지하며 desktop32/mobile44로 통일한다.

## 조건표

| 맥락 | 기본값/표시 | 동작 |
| --- | --- | --- |
| 데스크톱 탐색 펼침/접힘 | 상단 왼쪽에 동일 크기 토글 | 접힌 상태도 공간을 차지하는 레일; 본문 가리지 않음 |
| 모바일 탐색 | 드로어 닫힘 | 44px 열기/닫기, 배경과 Escape로 종료 |
| 로그인 사용자 | 계정 옆 개인 설정 | 한영·라이트/다크 전환 및 저장 |
| 관리자 머신 등록 | 이름, 선택 설명 | 등록 후 일회 토큰과 설치/실행/확인 안내 |
| 기존 오프라인 머신 | 연결 안내 | 저장 토큰으로 재연결, 유실시 토큰 재발급 경로 |
| 온라인 머신 | 엔진/에이전트 및 운영 상태 | 기존 검사·시작/중지·드레인·업데이트 기능 유지 |
| 에이전트 생성 | 이름·엔진·모델, 설명·초기 권한·참여 룸 | 선택한 머신을 실제 배치 요청에 전달; 허용되지 않는 머신/엔진 조합 거부 |
| 에이전트 생성의 활동로그 | 입력 없음 | 생성 후 상세에서 활동 확인 |
| 에이전트 워크스페이스 | 룸에 연결된 작업공간 사용 | 임의의 agent workspace 필드를 만들지 않고 룸 설정 경로 안내 |
| 에이전트 수정 | 저장된 설명·권한·룸 및 기존 설정 | 초기값을 보존하고 기존 모델/인증/활동/작업/책임 관리 접근 유지 |

## 구현과 검증

공통 CSS 크기 토큰과 UI primitive에서 밀도를 통제하고 새 생성 다이얼로그·머신 연결 안내를 별도 컴포넌트로 나눈다. 서버가 권한과 배치를 최종 검증한다. 기존 저장 설정·자동배치 호출은 호환한다. 외부 머신 설치나 토큰 회전은 실제 수행하지 않고 UI 경로와 mock 계약 테스트로 확인한다.

프론트엔드 빌드, 관련 컴포넌트/브라우저 테스트와 서버 생성·배치 테스트를 실행한다. 실제 로컬 로그인 및 기존 데이터의 읽기 전용 화면을 점검하고 375/768/1024/1440px, 한영·라이트/다크를 확인한다. 자동화는 크기·오버플로·클릭 도달성과 실제 API payload를 검증한다.
