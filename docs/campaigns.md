# 캠페인 — 지표를 정해 두고 계속 개선하기

캠페인은 **목적**과 **끝나는 기준**을 정해 두면 방 대표 에이전트가 시도를 반복하며 지표를 끌어올리는 기능입니다. 사이클마다 에이전트가 한 가지를 바꾸고, 정해 둔 평가 명령이 점수를 매깁니다. 점수는 에이전트의 보고가 아니라 평가 명령의 출력으로만 기록됩니다. 기준에 닿거나 예산·마감이 끝나면 멈추고, 마지막에 회고를 돌려 배운 것을 에이전트 지침에 남깁니다.

## 시작하기

1. 대표 에이전트가 있는 **프로젝트 방**을 엽니다. 오른쪽 패널의 **캠페인** 섹션에서 **새 캠페인**을 누릅니다. 방에서 작업을 관리할 수 있는 사람만 시작할 수 있습니다.
2. 제목과 **목적**을 적습니다. 목적은 에이전트가 사이클마다 읽으므로, 결과를 어디에 쓰는지 구체적으로 적습니다.
3. 끝나는 기준(모드), 지표 이름과 좋은 방향(높을수록/낮을수록), 평가 명령, 토큰 예산을 정합니다.
4. 시작하면 캠페인은 `진행 중`이 되고, 몇십 초 안에 첫 사이클 Task가 대표 에이전트에게 배정됩니다.

에이전트는 캠페인 도구를 MCP로 호출합니다. Codex 엔진은 권한 수준이 `trusted`가 아니면 MCP 도구가 아무 안내 없이 막히므로, Codex 대표 에이전트는 `trusted`로 설정하세요.

## 모드와 필요한 입력

| 모드 | 끝나는 기준 | 목표 점수 | 마감 시각 | 정체했을 때 |
|---|---|---|---|---|
| 목표 점수에 도달하기 (`target`) | 점수가 목표에 닿으면 멈추고 결과 확인을 요청 | 필수 | 선택 | 5사이클 동안 개선이 없으면 `정체` |
| 마감까지 계속 개선하기 (`optimize`) | 마감 시각까지 개선을 이어가고 가장 좋은 시도를 남김 | 받지 않음 | 필수(미래 시각) | 멈추지 않고 다음 사이클에 전략을 바꾸라고 지시 |

두 모드 모두 **토큰 예산이 필수**입니다. 예산의 5%(API의 `budget.retro_reserve_ratio`로 0–50% 조정)는 마무리 회고용으로 남겨 두고, 사이클은 나머지만 씁니다. 사이클 사이에는 최소 5분 간격이 있습니다. `min_delta`보다 크게 좋아져야 `개선`으로 칩니다.

## 평가 명령 규칙

평가 명령은 대표 에이전트가 배치된 머신에서, 그 에이전트의 작업 공간 안에서 실행됩니다.

- `/bin/sh -c <명령>`으로 `작업 공간/<작업 폴더>`에서 실행합니다. 작업 폴더는 작업 공간 밖을 가리킬 수 없습니다.
- 종료 코드 0으로 끝나고, stdout의 **마지막 줄**에 JSON 객체 하나를 출력해야 합니다. 객체에는 점수 필드(기본 `score`, 바꿀 수 있음)의 숫자와 `valid`(불리언)가 있어야 합니다.

  ```
  {"score": 0.87, "valid": true}
  ```

- `valid`는 가드레일 통과 여부이며 판정은 평가 스크립트가 합니다. `valid: false`면 점수가 좋아도 `가드레일 위반`으로 기록되고 최고 기록이 되지 않습니다.
- 제한 시간은 기본 600초, 최대 6시간입니다. 넘기면 프로세스 그룹 전체를 종료하고 `채점 실패`로 닫습니다. 서버는 제한 시간에 120초를 더 기다린 뒤에도 결과가 없으면 같은 방식으로 닫습니다. 늦게 온 결과는 기록만 남고 점수가 되지 않습니다.
- 비밀값은 전달하지 않습니다. 환경 변수는 `PATH`, `HOME`, 로캘, 임시 폴더만 넘깁니다.
- **고정 파일(pin)**: 에이전트가 바꾸면 안 되는 파일·폴더를 지정하면 첫 평가 때 해시를 기록하고, 이후 해시가 달라지면 평가를 돌리지 않습니다. 그 시도는 `무효 결과`가 되고 캠페인은 `막힘`이 됩니다.
- 머신이 오프라인이거나 다른 평가를 돌리는 중이면 평가는 대기하다가 다시 요청됩니다. 머신 한 대는 한 번에 평가 하나만 돌립니다.
- 평가 명령은 그 머신에서 실행되므로, **에이전트 머신의 소유자나 관리자만** 정하거나 바꿀 수 있습니다.

## 상태와 할 일

| 상태 | 뜻 | 할 수 있는 일 |
|---|---|---|
| 진행 중 | 사이클을 돌리고 있음 | 일시 정지, 중단, 목적·기준·예산 수정 |
| 일시 정지 | 새 사이클을 열지 않음(진행 중인 사이클은 마저 끝남) | 재개, 중단 |
| 막힘 | 평가 3회 연속 실패, 고정 파일 변경, 에이전트가 사람의 도움을 요청, 대표 에이전트가 방을 떠남 | 원인(이유는 캠페인에 표시)을 해결하고 재개 |
| 정체 | 목표 모드에서 5사이클 동안 개선 없음 | 목적·기준을 고치고 재개, 또는 중단 |
| 확인 필요 | 점수가 목표에 닿음 | **결과 확인**(달성으로 끝냄) 또는 **아직 아님, 계속** |
| 달성 | 확인했거나 검증된 점수가 목표에 닿음 | — (끝) |
| 마감 도달 · 예산 소진 | 마감이 지났거나 예산을 다 씀 | **연장**: 끝낸 마감이나 예산보다 늘리면 다시 진행 |
| 중단됨 | 사람이 중단했거나 방이 보관됨 | — (끝, 회고 없음) |

- 수정한 내용은 다음 사이클부터 적용되고, 진행 중인 사이클의 에이전트에게는 후속 지시로 전달됩니다.
- 끝난 캠페인의 최종 결과는 검증된 점수 1위, 없으면 dev 점수 1위(미검증 표시)입니다. 끝난 뒤에는 API(`select-final`)로 다른 시도를 최종 결과로 고를 수 있습니다.
- **외부 검증**: 고급 설정의 "Anygarden 밖에서 검증한 점수를 기다림"을 켜면, dev 점수가 목표에 닿아도 `확인 필요`에서 기다리고, `POST /api/v1/campaigns/{id}/attempts/{attempt_id}/trusted-score`로 기록한 검증 점수가 목표에 닿을 때 `달성`이 됩니다. 사람이 직접 결과를 확인해 끝낼 수도 있습니다.
- 방을 보관하면 그 방의 캠페인은 즉시 중단되고 열린 사이클도 닫힙니다.
- 사이클 Task는 캠페인이 관리합니다. 열린 사이클 Task의 상태를 일반 Task 화면이나 API로 바꾸거나 지울 수 없습니다(409). 캠페인을 멈추려면 캠페인의 일시 정지·중단을 쓰세요.
- 결과가 불분명한 사이클(실행 시간 초과, Task 소실 등)은 다시 돌리지 않고 `알 수 없음`으로 남긴 채 다음 사이클로 넘어갑니다.

## 회고와 학습

회고는 10사이클마다, 그리고 캠페인이 달성·마감 도달·예산 소진으로 끝날 때 한 번 돕니다. 중단한 캠페인은 회고하지 않습니다. 끝날 때의 회고는 남겨 둔 예약분 토큰 안에서 돕니다.

회고에서 에이전트는 배운 것을 지침에 반영합니다. **승인 없이 바로 적용**되며 다음과 같이 제한됩니다.

- AGENTS.md는 `## Campaign learnings` 섹션의 본문만 바꿉니다(없으면 만듭니다). 섹션 밖은 수정할 수 없습니다.
- 스킬은 새로 만들거나, 이 캠페인이 만든 스킬만 고칩니다.
- 회고 한 번에 최대 3건, 건당 16KB까지입니다.

변경마다 `source=campaign` 지침 리비전(근거 포함), 캠페인 이벤트, 방 메시지가 남습니다. 마음에 들지 않으면 에이전트 설정의 **지침 변경 이력**에서 **이 버전으로 되돌리기**로 이전 리비전을 복원합니다.

## 에이전트가 쓰는 도구

사이클 Task를 받은 에이전트는 평소처럼 `begin_project_execution`으로 실행을 시작하고 `complete_project_execution`으로 끝냅니다. 실행의 토큰 한도와 마감은 캠페인의 남은 예산·마감으로 줄어듭니다. 그 사이 다음 도구를 씁니다.

| 도구 | 용도 |
|---|---|
| `record_campaign_attempt` | 이번 사이클에서 시도한 것(가설·변경·산출물·교훈)을 기록. 사이클당 한 번, 평가 시작 전에만. 응답에 사이클 시작 뒤 들어온 후속 지시가 담김 |
| `schedule_campaign_wakeup` | 이번 사이클이 끝난 뒤 **다음** 사이클을 특정 시각 이후로 미룸(60초–7일, 마감 전). 외부 리더보드·평가 결과를 기다릴 때 씀. 이번 사이클 안에서 자기 하위 작업을 기다리는 용도가 아님(턴을 끝내면 서버가 결과 도착 시 다시 깨움) |
| `report_campaign_blocked` | 사람의 도움 없이는 진행할 수 없음을 알림. 사이클이 닫히면 `막힘` |
| `read_campaign_attempts` | 지난 시도를 최신순으로 읽음 |
| `apply_campaign_learning` | 회고 사이클에서만. AGENTS.md 학습 섹션이나 스킬을 갱신 |

기록 없이 끝난 사이클은 `기록 없음`으로 남습니다.

캠페인 사이클은 하위 방 없이 대표 에이전트가 직접 일해도 됩니다. 최소 순서는 `begin_project_execution` → 작업 → `record_campaign_attempt` → `seal_project_plan`(`required_task_ids=[]`) → `complete_project_execution`이며, 회고도 기록 없이 같은 순서로 끝납니다. 하위 작업 없이 계획을 확정할 수 있는 것은 캠페인 사이클뿐이고, 일반 프로젝트 실행은 여전히 하위 작업이 하나 이상 있어야 합니다.

## 한계와 보안

- 평가 명령은 **에이전트와 같은 머신에서 같은 사용자로** 실행됩니다. 고정 파일 해시는 실수나 단순한 수정을 막는 수준이며 격리가 아닙니다. 격리된 신뢰 평가는 #931에서 다룹니다.
- 연합(다른 노드와의 협업)은 **서로 신뢰하는 노드끼리만** 한다는 전제입니다. 원격 노드 에이전트를 사이클의 일부로 쓰는 일은 #933에서 다룹니다.
- 에이전트가 자기 자신(Anygarden 코드나 자기 평가기)을 개선 대상으로 삼는 캠페인은 이번 범위가 아니며 #931에서 다룹니다.
